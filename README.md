# 书流 Shuliu — 用「刷」的方式打开经典文学

> 片段流 → 兴趣冷启动 → 行为学习 → 个性化推荐 → 进入原文

把《红楼梦》《西游记》等 10 本公版经典拆成 76 条 60~220 字的独立片段，以短视频式信息流呈现：选 3 个兴趣冷启动，每次上滑、喜欢、收藏都在本地更新兴趣画像，推荐随行为持续变化，随时一键进入原文完整章节。

- 在线体验（PWA）：https://wangsehn.github.io/shuliu/
- 全部计算在客户端完成，无服务器、无登录、无第三方上报；数据存本机 localStorage

## 00 快速体验（3 种方式）

**方式一 · 浏览器直接玩（无需安装）**

打开 https://wangsehn.github.io/shuliu/ → 选 3 个兴趣 → 开始刷。

- 电脑：鼠标滚轮 / ↑↓ 方向键 / 按住拖拽均可翻页，双击正文点赞
- 手机：上滑翻页，浏览器菜单「添加到主屏幕」后可作为独立 App 运行（PWA，支持离线）

**方式二 · Android 安装包**

到 [Releases](https://github.com/wangsehn/shuliu/releases) 下载 `shuliu-v1.0-release.apk` → 手机上点开安装（提示未知来源时允许即可）→ 数据全部保存在本机。

**方式三 · 本地运行**

```bash
git clone https://github.com/wangsehn/shuliu.git
cd shuliu
python -m http.server 8931   # 浏览器打开 http://localhost:8931
```

> 数据与隐私：所有行为数据（滑动、停留、喜欢、收藏）仅存在本机浏览器/设备中，用于本地兴趣画像计算，不上传任何服务器。「我的 → 清除本机记录」可一键重置冷启动。

## 01 问题

经典文学阅读启动成本高：用户不知道从哪读起。大部头劝退、选书困难、读两页就放下。现有阅读产品解决「读完」，不解决「开始读」。

## 02 核心机制

信息流的分发逻辑 + 文学的内容密度：片段足够短所以能「刷」，片段背后挂着完整章节所以能「读进去」。

```mermaid
flowchart LR
  A[兴趣选择<br>冷启动] --> B[片段流<br>上滑/喜欢/收藏/不感兴趣]
  B --> C[行为埋点<br>本机事件环 500 条]
  C --> D[兴趣画像<br>主题权重 + 最近触达]
  D --> E[衰减排序<br>score = 权重 x 0.5^天数/7]
  E --> F[组装约束<br>同书不连续 / 5窗<=2 / 探索位 1/4]
  F --> B
  F --> G[进入原文<br>定位高亮续读]
```

## 04 推荐系统设计

**6 类行为事件闭环**（V1 已上线）：

| 事件 | 信号 | 画像更新 |
|---|---|---:|
| like / unlike | 中正向 | +1.0 / −1.0 |
| save / unsave | 强正向 | +1.2 / −1.2 |
| view_complete（停留 ≥4s） | 中正向 | +0.3 |
| quick_skip（<4s 上滑） | 弱负向 | 连续 2 次同主题才 −0.5（防误伤） |
| open_original | 强正向 | 进原文权重 |
| not_interested | 强负向 | −0.5 且隐藏该片段 |

**排序与多样性硬约束**（每轮组装必须满足）：

- 冷启动首 4 条 ≥3 条命中所选兴趣
- 同书不连续；任意 5 连窗口内同书 ≤2 条
- 任意 4 连窗口 ≥1 条探索位（低亲和内容，占比约 1/4，防信息茧房）
- 时间衰减：score = 主题权重 × 0.5^(距上次触达天数 / 7)

**每条推荐都给理由**：「和你喜欢过的内容相似」/「因为你喜欢过『XX』相关内容」/「因为你选择了『XX』」/「给你一段新的文学发现」——零亲和不编造行为。详见 [推荐系统 PRD](推荐系统核心功能PRD.md)。

## 05 Baseline vs V2（离线重放评估）

4 个合成人设 × 24 轮重放（76 条片段），对比旧「3 匹配 + 1 其他」静态混排基线。**未宣称全场景更好，而是用重放验证「推荐随行为学习」这件事真实发生**：

| 人设 | 后程命中率 基线 → V2 | 结论 |
|---|---|---|
| P1 声明[亲密关系]+潜在[成长] | 52.9% → **75.0%** | V2 优（+22.1pp） |
| P2 声明[孤独,情绪]+潜在[人性] | 87.1% → 75.0% | 未超越（声明过宽已覆盖偏好，基线天然占优） |
| P3 无声明+潜在[亲密,孤独] | 26.3% → **75.0%** | V2 优（**+48.7pp**） |
| P4 声明[自我认识]+潜在[成长] | 67.9% → **75.0%** | V2 优（+7.1pp） |

关键在于 P3：用户没选任何兴趣时，基线只能随机，V2 靠行为反馈把命中率拉到与声明用户相同水平。全程组装硬约束零违规（同书/5窗/探索位/重复），性能 buildFeed p95 = 0.665ms（76 条全量）。复现：`node tests/replay_eval.js`，完整数据见[验收记录](验收记录.md)。
